# Чек на удачу

Тестовое приложение промо-акции: покупатель отправляет чек, а staff-модератор проверяет его через Django admin.

## Запуск

1. Скопируйте `.env.example` в `.env` и задайте безопасные значения `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`.
2. Выполните `docker compose up --build`.
3. Откройте [http://localhost:3000](http://localhost:3000). Страницы входа и регистрации доступны по `/accounts/login/` и `/accounts/register/`.
4. Для модератора создайте пользователя: `docker compose exec backend python manage.py createsuperuser`, затем откройте `http://admin.localhost:3000/admin/`. Этот адрес использует отдельную сессию от пользовательского сайта `http://localhost:3000`.

## Реализовано

- Django-модель чека с ФН, ФД, ФП, покупкой, суммой, статусом, причиной отказа, пользователем и датой регистрации.
- Серверная валидация периода акции из env, суммы от 1 000 ₽, цифровых реквизитов и глобальной уникальности ФН+ФД+ФП.
- Сессионный API `GET` и `POST /api/receipts/`, который всегда возвращает и создаёт только чеки текущего пользователя; список отсортирован от новых к старым и разбит по 10 записей.
- Обычная Django admin для staff, где причина обязательна при отклонении.
- Next.js-экраны регистрации и личного кабинета: адаптивная вёрстка, inline-валидация, `fetch` + CSRF, статусы успеха и ошибки.
- Docker Compose с PostgreSQL, Django, Next.js и Nginx. Nginx проксирует `/api`, `/admin` и `/accounts` к Django, напрямую отдаёт `/static/` и сохраняет для браузера один origin.

## Сверх задания

- Автоматические Django-тесты валидации, доступа к API и пагинации.
- Поле QR-строки с разбором `t`, `s`, `fn`, `i`, `fp` и автозаполнением формы.

## Принятые решения

- Период акции — включительные календарные даты в `TIME_ZONE` (по умолчанию `Europe/Moscow`).
- Отклонённый чек отправить заново нельзя: уникальность фискальной тройки глобальная, как требует ТЗ.
- ФН, ФД и ФП — строки без заданных длин и с сохранением ведущих нулей; принимаются только цифры.
- Список «новые к старым» сортируется по моменту регистрации заявки.
- Для статуса «Отклонён» причина обязательна; при другом статусе она очищается.

## Проверки

В контейнере: `docker compose exec backend python manage.py test`.
